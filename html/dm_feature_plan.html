ダイレクトメッセージ (DM) 機能 実装計画

1. 概要

ユーザーがプロフィール画面から「メールアイコン」をタップした際に、そのユーザーとの1対1のチャット（DM）画面を開き、メッセージの送受信を行えるようにします。

2. データベース設計 (Supabase SQL)

1対1のチャットを実現するため、ルーム(部屋)、ルームメンバー、メッセージの3つのテーブルを作成します。

2.1. テーブル定義

-- 1. DMルームテーブル
CREATE TABLE public.dm_rooms (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 2. DMルームメンバーテーブル (誰がどのルームに参加しているか)
CREATE TABLE public.dm_room_members (
    room_id UUID REFERENCES public.dm_rooms(id) ON DELETE CASCADE,
    user_id UUID REFERENCES public.users(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (room_id, user_id)
);

-- 3. DMメッセージテーブル
CREATE TABLE public.dm_messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    room_id UUID REFERENCES public.dm_rooms(id) ON DELETE CASCADE,
    sender_id UUID REFERENCES public.users(id) ON DELETE CASCADE,
    content TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    is_read BOOLEAN NOT NULL DEFAULT false
);

2.2. RPC (ストアドプロシージャ) の作成

「すでに相手とのルームが存在すればそのIDを返し、なければ新しくルームを作成してIDを返す」便利な関数を作成します。

CREATE OR REPLACE FUNCTION get_or_create_dm_room(other_user_id UUID)
RETURNS UUID
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
    v_my_id UUID;
    v_room_id UUID;
BEGIN
    -- 自分のユーザーIDを取得
    v_my_id := auth.uid();
    
    IF v_my_id IS NULL THEN
        RAISE EXCEPTION 'Not authenticated';
    END IF;

    -- 既に1対1のルームが存在するか確認
    SELECT r.id INTO v_room_id
    FROM dm_rooms r
    JOIN dm_room_members m1 ON r.id = m1.room_id AND m1.user_id = v_my_id
    JOIN dm_room_members m2 ON r.id = m2.room_id AND m2.user_id = other_user_id
    LIMIT 1;

    -- 存在しなければ作成
    IF v_room_id IS NULL THEN
        INSERT INTO dm_rooms DEFAULT VALUES RETURNING id INTO v_room_id;
        INSERT INTO dm_room_members (room_id, user_id) VALUES (v_room_id, v_my_id);
        INSERT INTO dm_room_members (room_id, user_id) VALUES (v_room_id, other_user_id);
    END IF;

    RETURN v_room_id;
END;
$$;

2.3. RLS (Row Level Security) の設定

自分が参加しているルームの情報やメッセージのみを取得・追加できるようにセキュリティルールを設定します。

3. Flutterアプリ側の実装設計

3.1. プロフィール画面の改修 (lib/views/UserProfilePage.dart)

メールアイコン（Icon(Icons.mail_outline)）の onPressed に処理を追加します。

  • タップ時に Supabase.instance.client.rpc('get_or_create_dm_room', params: {'other_user_id': userId}) を呼び出し、対象の roomId を取得。
  • 取得した roomId と userId（相手）を引数にして DmRoomPage へ画面遷移（Navigator.push）。

3.2. チャット画面の作成 (lib/views/DmRoomPage.dart)

1対1のチャット画面を新規作成します。

  • ヘッダー: 相手のユーザー名とアイコンを表示。
  • メッセージリスト: Supabase.instance.client.from('dm_messages').stream(...) を用いて、リアルタイムにメッセージを購読（StreamBuilder または Riverpod の StreamProvider）。
  • 入力フォーム: 下部にテキストフィールドと送信ボタン。送信時に dm_messages テーブルへ insert。

3.3. 状態管理 / プロバイダー (lib/provider/dm_provider.dart 等)

メッセージ送信処理や、Streamプロバイダーを定義して、Viewとロジックを分離します。

4. 今後のステップ

  1. SupabaseコンソールのSQLエディタ等で上記SQLを実行し、テーブルとRPCを作成する。
  2. Flutter側で必要なプロバイダー・ViewModelを作成する。
  3. チャット画面のUI（DmRoomPage.dart）を作成する。
  4. UserProfilePage.dart のボタンから遷移できるように組み込む。
