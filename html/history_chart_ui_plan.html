履歴画面 レーダーチャート表示 UI改善設計書

情報量増加に伴う画面構成の最適化案と、インタラクティブモックアップ

現状の課題とUI刷新の必要性

現在、FinishPage（対戦終了画面）ではAIジャッジによる「5項目のレーダーチャート」および「論理能力%」が表示されています。 これを履歴画面でも振り返れるようにしたいですが、現在の履歴一覧カードは「テーマ」「自分の選択」「勝敗理由」がすでに詰め込まれており、ここにレーダーチャート（高さ約200px）をそのまま入れると1枚のカードが画面の半分以上を占拠し、一覧性が大幅に悪化します。

1カードの肥大化

1画面に1〜2件しか表示できなくなり、過去の勝敗履歴をスクロールして探すのが困難になります。

レーダーチャートの視認性

リストの隙間に無理やりチャートを小さく押し込むと、5項目（論理性・説得力・反論力・構成力・マナー）のラベルや数値が読み取れなくなります。

階層構造の欠如

「一覧でざっと勝敗を見る」と「特定の試合のAI評価・チャート・ログを詳しく振り返る」の2つの目的が1画面に混在してしまいます。

Flutter 実装方針とデータフロー

1. modes/history.dart の拡張

MatchRecordDisplay に scores（MatchScores?）フィールドを追加します。

class MatchRecordDisplay { final String roomid; final String resultString; // "勝利" / "敗北" final int trophyChange; final String opponentName; final String? opponentAvatarUrl; final String theme; final String userChoice; final String reason; final bool? cancel; final String? opponentid; final bool isUnderdog; // ★ 追加: スコア情報（レーダーチャート用） final MatchScores? scores; MatchRecordDisplay({ required this.roomid, ... this.scores, }); }

2. provider/history_provider.dart でのパース処理

Supabaseの match_record テーブルの scores カラムを読み込んでマッピングします。

// scoresのパース MatchScores? scores; if (record['scores'] != null) { if (record['scores'] is Map<String, dynamic>) { scores = MatchScores.fromMap(record['scores'] as Map<String, dynamic>); } else if (record['scores'] is String) { scores = MatchScores.fromJsonString(record['scores'] as String); } } return [ MatchRecordDisplay( roomid: roomid, resultString: resultString, trophyChange: trophyChange, opponentName: opponentName, opponentAvatarUrl: opponentAvatarUrl, opponentid: opponentid, theme: theme, userChoice: userChoice, reason: formattedReason, cancel: cancel, scores: scores, // ★ ここに渡す ) ];

3. RadarChartView の活用
