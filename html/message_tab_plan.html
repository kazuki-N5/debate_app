📱 メッセージタブ 構成設計 & モック画面

「通知」と「メッセージ（DM / オプチャ）」を1つのタブに統合した画面の設計案・モック・実装ロードマップ

1. 概要と方針

📩 メッセージタブ（MessagePage 改修）
  • セグメント①：通知 必須
    • ポスト / 返信コメントのいいね通知 必須
    • フォロー通知 必須
    • コメントに対する返信の通知 必須
  • セグメント②：メッセージ 必須
    • DM 一覧・表示 必須 DmRoomPage 既存
    • オプチャ メッセージ 必須 OpenChatRoomView 既存
  • 未読バッジ（タブ・セグメント・アイコン） 実装必要
  • リアルタイム反映（Supabase Realtime） 実装必要
💡 設計方針：既存の NotificationPage と MessagePage は仮実装のままなので、メッセージタブ1画面に「通知」と「メッセージ（DM・オプチャ）」のセグメント切替を統合します。 通知の各項目をタップすると既存の BbsPostDetailView（ポスト詳細）・UserProfilePage（フォロー）・DmRoomPage（DM）・OpenChatRoomView（オプチャ）へ遷移します。

🔔 通知セグメントの仕様

  • 初期表示は「通知」。未読があればバッジ「6」表示
  • 通知アイコン（💬=返信 / ❤️=いいね / ＋=フォロー）で種別をひと目で判別
  • いいね通知：ポスト・返信コメント両方に対応（種別フィールドで区別）
  • フォロー通知：相手のプロフィールへ遷移
  • 返信通知：元コメントの引用表示 → タップでポスト詳細へ
  • 未読は背景色 + 太字で強調。開封で既読化
  • 「すべて既読にする」ボタン（未実装）

⚠️ いいね・返信は重複排除を検討：同じ相手から同じ対象への連続いいねは最新1件にマージ（UNIQUE (user_id, actor_id, type, post_id/comment_id) + upsert）しないと通知が大量に積み上がります。

7-2. ⚠️ 事前に Supabase で SQL を実行してください

通知テーブル・フォローテーブル・通知自動生成トリガーは Supabase 側に存在しないため、 先に sql/message_tab.sql を実行しないとアプリ側の通知一覧が動きません。
手順：Supabase ダッシュボード → SQL Editor → sql/message_tab.sql の内容を貼り付け → Run

7-3. 通知の自動生成ルール（アプリ側コード変更不要）

操作通知 type生成場所
ポストにいいね / いいね解除like_post / 削除bbs_likes の INSERT/DELETE トリガー
コメントにいいね / いいね解除like_comment / 削除bbs_comment_likes の INSERT/DELETE トリガー
コメントへの返信reply_commentbbs_comments の INSERT トリガー（parent_comment_id ありのみ）
フォロー / 解除follow / 削除user_follows の INSERT/DELETE トリガー
💡 同じ相手からの連続いいねは、通知を一度削除してから再生成するため重複しません（再いいねで最新化）。

7-4. 動作確認手順

  1. SQL実行後、アプリを再ビルドしてメッセージタブを開く
  2. 自分のポスト/コメントに別アカウントでいいね → 通知タブに即時反映（Realtime）
  3. 自分のコメントに返信 → reply_comment 通知
  4. プロフィール画面の❤️ボタンでフォロー → follow 通知
  5. DM・オプチャのやり取りがメッセージタブに一覧表示される
