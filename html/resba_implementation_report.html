⚔️ レスバ機能 実装まとめ・エッジケース解説

ポスト / 返信 / DM に「レスバ」を付けて対戦する機能の実装全体像と、アプリを閉じたとき・途中でやめたとき等の詳細な挙動

1. 実装した機能の全体像

コンテンツにレスバを付ける
ポスト / 返信 / DM → 相手が承諾 or 応募者を承認
全画面ダイアログ / 応募中バナー → rooms_v2 で試合開始
両者 /wait へ自動遷移 → 試合終了
勝敗確定・レスバは finished
機能説明
レスバの作成ポスト作成時・返信入力欄（📷の隣に⚔️）・DM入力欄（📷の隣に⚔️）からテーマ/選択肢を設定して送信。本文が空でもレスバだけ送信可
指名型（返信 / DM）相手が最初から決まっている（返信先・DMの相手）。相手に「⚔️ レスバが届きました」→ 承諾/拒否
募集型（ポスト）誰でも「⚔️ 応じる」。応募者はホストの全画面ダイアログに1件ずつ表示 → 承認/拒否
ホストの全画面ダイアログ応募が来た瞬間に「⚔️ 申し込みが来ました」（応募者名・テーマ）を表示。閉じる操作不可（はい・いいえを押すまで残る）
応募中バナーアプリ画面上部に常駐（タブ切替と無関係に固定）。「⚔️ 申し込み中（◯◯さんのレスバ）」+ 取り消すボタン
拒否されたときバナーが「⚔️ 拒否されました」（黒背景・白文字）に変わり 0.8秒で自動消去
応募の入れ替え応募中に別のレスバへ応じようとすると「今の応募を取り消して入れ替えますか？」→ はい/いいえ
マイレスバホーム右上の⚔️アイコンから一覧表示（募集中/履歴タブ）。取り下げ・削除・対戦へ戻る
試合への自動遷移承諾・承認された瞬間、両者がRealtimeで検知して /wait へ（送信者はリスナー、相手はダイアログ/カードから直接）
対戦中判定「試合は1つだけ」という前提。新しい試合に関わる操作をした瞬間、前の進行中ルームを「負け（相手勝ち）」として確定してから操作を続行（待ち時間ゼロ）

2. データモデル

bbs_posts / bbs_comments / dm_messages
コンテンツ attach_type + attach_id battle_invites
レスバ本体 1─N battle_invite_applications
応募（ポスト型） battle_room_id rooms_v2
試合
テーブル主なカラム状態
battle_invitessender_id / attach_type(post・comment・dm) / attach_id / target_user_id / theme / choice1・2 / status / responder_id / battle_room_idpending → accepted / declined / cancelled / finished
battle_invite_applicationsinvite_id / applicant_id / statuspending → accepted / rejected / cancelled（同時1件・重複禁止はDB制約）
rooms_v2player1 / player2 / current_theme / winner / is_bbs進行中（winner NULL）→ 勝敗確定（A/B/C）

3. エッジケース詳細（エラーが起きそうな状況）

3.1 アプリを閉じたとき

閉じたときの状態DBに何が残るか再開後の挙動
試合中に閉じた rooms_v2 に進行中ルーム（winner NULL・player2確定）が残る 次の「試合に関わる操作」（レスバ送信・応募・ランダム）をした瞬間、is_user_in_battle が前の試合を「負け（相手勝ち）」として確定して解除 → ブロックなしで操作可能。
※ 相手には「勝ち」が入る（アプリを切った方が悪い、という仕様）
応募中に閉じた battle_invite_applications の pending が残る 再開すると応募中バナーが復活（「⚔️ 申し込み中」）。ホストが承認すれば両者 /wait へ自動遷移。
自分で「取り消す」も可能
ホスト（募集中）で閉じた battle_invites の pending と、来ていた応募が残る 再開時に未対応の応募があれば全画面ダイアログを再表示（アプリ起動時チェック）。ホームの「保留中の応募があります」バナーからも対応可能
相手がレスバを承諾していない状態で閉じた battle_invites の pending（相手待ち）が残る 再開後も「相手待ち」のまま。マイレスバから取り下げできる。相手が承諾すれば /wait へ

3.2 途中でやめたとき（取り下げ・キャンセル）

操作結果相手・画面への影響
応募者側が「取り消す」（バナー or カード） 応募が cancelled になる バナーが消える。ポスト詳細では「⚔️ 応じる」ボタンが再表示され、再応募できる。ホスト側のダイアログには出ない
ホストが募集を取り下げる（マイレスバ） レスバが cancelled になる 応募者側の応募も取り下げ扱いになり、ポスト詳細で再応募可能に（レスバ自体が募集中でなくなるためカードは消える）
送信者が指名型（返信/DM）を取り下げる レスバが cancelled になる 相手側の「⚔️ レスバが届きました」カードが「取り下げられました」表示になる
レスバ送信後、相手が応答しない pending のまま残る マイレスバからいつでも取り下げ可能。自動キャンセルはしない（相手待ちは待つ）

3.3 拒否されたとき

状況挙動
指名型（返信/DM）の相手が拒否 レスバが declined に。送信者側のカードが「拒否されました」表示になる
ホストが応募を拒否（全画面ダイアログで「いいえ」） 応募が rejected に。応募者側に「⚔️ 拒否されました」バナーが0.8秒表示されて消える。
ポスト詳細では応募ボタンが押せない（「拒否されました」表示・再応募不可）

3.4 同時操作（競合）

状況結果
応募者「取り消す」とホスト「承認」が同時 DBの行ロック（FOR UPDATE）で直列化。先に来た方だけが有効になり、後から来た方は「受付終了しています」等でエラー（二重処理は起きない）
応募者がランダムマッチ等で対戦中に、ホストが承認 承認RPCが応募者の対戦状態をチェック。**ただし「解決型」のため、進行中ルームがあれば「負け」に確定して承認が通る**（新しい試合のための前試合破棄）
ホストが対戦中に、相手が承諾 承諾RPCが送信者の対戦状態をチェック → 進行中ルームがあれば「負け」に確定して承諾が通る（二重試合にはならない）
応募中に別のレスバへ応じる 「入れ替え確認」ダイアログ → はい: 前の応募を取り消して新応募 / いいえ: 何もしない

3.5 未選択・放置（試合の終了）

状況挙動
相手が選択（回答）せずタイムアウト ChosePage のタイマーが「相手が選択しませんでした」→ 自分の勝ち（winner設定）を確定してからホームへ。対戦中が残らない
自分が選択せずタイムアウト 相手の勝ち（winner設定）→ ホームへ
両者ともアプリを閉じて放置 cron（5分毎）が3分以上更新の無いルームを引き分け終了（winner='C'）→ 誰も操作しなくても掃除される
アプリを開いた直後 操作時解決（is_user_in_battle）と cron の両方で、古い進行中ルームは「負け or 引き分け」で処理される

3.6 Realtime・ネットワーク障害

状況挙動
Realtime未設定（publication未登録） ホストの全画面ダイアログ・応募中バナー・自動遷移が動かない。→ 20260818120000_ensure_resba_realtime.sql 適用が必要（battle_invites / battle_invite_applications / rooms_v2 を supabase_realtime に登録）
サーバー接続失敗（AuthRetryableFetchException 等） 認証トークン更新やRPC呼び出しが失敗。アプリは通常、エラーSnackBarや状態のまま。サーバー（Supabase）再起動で復旧
RPC呼び出し中の通信断 応募・承諾などの操作が失敗 → エラーメッセージ表示。DBには書き込まれていない（成功するまで再試行）

4. エラーコード一覧

コード意味フロントの表示
IN_BATTLE自分が進行中ルームを持つ解決型のため基本的に出ない（前の試合を負けに確定して許可）
SENDER_IN_BATTLE送信者（ホスト）が進行中同上（解決して許可）
APPLICANT_IN_BATTLE応募者が進行中同上（解決して許可）
ALREADY_APPLYING応募中の応募がある「現在応募中のレスバがあります。先にキャンセルしてください」
INVITE_CLOSED締切・成立・取消済み「このレスバは受付終了しています」
NOT_TARGET / NOT_HOST権限外の操作操作不可表示
SELF_INVITE / SELF_APPLY自分自身への送信「自分自身には送信できません」
NOT_FOUND_OR_UNAUTHORIZED対象が無い・権限なし「失敗しました」

5. トラブルシューティング（よくある症状と対処）

症状原因と対処
試合後にポストが開けない（タップが無視される） ポストカードの連打防止フラグ（_isNavigating）が true のまま残る問題。3秒で自動リセットする保険を実装済み（navigatorKey 復活でも解消）。再発したらアプリ再起動で復旧
ホストの全画面ダイアログが出ない 「Navigator operation requested with a context that does not include a Navigator」→ navigatorKey（Navigator の子孫のcontext）経由に修正済み。それでも出ない場合は publication 未登録を確認（§3.6）
「対戦中です」と出てレスバを送れない 進行中ルームが残っている（旧仕様）。現在は「操作時に前の試合を負けに確定して解除」するため解消。古いデータは cron が掃除
応募中バナーが表示されない publication 未登録 or ログイン前の初期化タイミング。バナーはログイン後に HomePage 表示で購読開始
「拒否されました」が出ない rejected 検知の Realtime イベント依存。publication 未登録なら届かない（§3.6 を確認）
